## Persona: Isaac — Integration Developer

**Role**: Integration Developer / Architect  
**Technical Level**: Medium–High (understands APIs, data formats, flow logic; may prefer no-code for speed)  
**Environment**: IBM IWHI platform; may also use other integration tools

### Goals
- Quickly create flow services and workflows without writing boilerplate
- Iterate on integrations through conversation rather than form-filling
- Test and deploy integrations with minimal context switching

### Pain Points
- Setting up integrations from scratch is slow and repetitive
- Debugging errors requires navigating multiple screens
- Hard to understand what the agent is doing or has done (transparency)

### What They Use Flow Agent For
- Creating new flow services via natural language
- Modifying existing integrations
- Asking questions about integration patterns
- Monitoring integration health (secondary)

### Key Design Considerations
- Needs to trust the agent — show what was created and why
- Wants to verify before deploying — workspace view is critical
- May switch between chat and manual editing — agent must not break manual changes
